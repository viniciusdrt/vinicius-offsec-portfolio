# Política de Segurança

## Versões Suportadas

Este projeto corresponde ao PortfolioHUB pessoal de Vinícius, publicado por meio do GitHub Pages.

Atualmente, a versão principal mantida é a versão publicada na branch `main`.

| Versão          | Suporte        |
| --------------- | -------------- |
| main            | Suportada      |
| versões antigas | Não suportadas |

## Relato de Vulnerabilidades

Caso alguma vulnerabilidade, erro de configuração ou exposição indevida seja identificada neste projeto, ela poderá ser comunicada por meio dos canais de contato disponíveis no PortfolioHUB.

O objetivo é permitir que possíveis problemas sejam corrigidos de forma responsável e organizada.

## Cuidados de Segurança do Projeto

Este projeto foi desenvolvido como um site estático, utilizando HTML, CSS e JavaScript.

Por esse motivo, o PortfolioHUB não realiza:

* Cadastro de usuários;
* Login ou autenticação;
* Armazenamento de senhas;
* Coleta de dados sensíveis;
* Integração com banco de dados;
* Processamento de pagamentos;
* Uso de tokens ou chaves de API no front-end.

## Informações Sensíveis

O repositório não deve conter:

* Senhas;
* Tokens de acesso;
* Chaves privadas;
* Chaves de API;
* Arquivos de configuração com credenciais;
* Dados pessoais sensíveis;
* Informações internas ou privadas.

Antes de cada alteração, os arquivos devem ser revisados para evitar a publicação acidental dessas informações.

## Controle de Acesso

O repositório é público para fins de apresentação profissional, porém apenas o proprietário possui permissão direta para alterar os arquivos e configurações do projeto.

Contribuições externas, caso ocorram futuramente, devem ser realizadas por meio de Pull Requests, permitindo revisão antes da integração com a branch principal.

## Boas Práticas Aplicadas

Durante a implantação do PortfolioHUB, foram consideradas as seguintes boas práticas:

* Manter o código-fonte versionado no GitHub;
* Utilizar GitHub Pages para publicação de site estático;
* Evitar exposição de credenciais;
* Revisar arquivos antes dos commits;
* Manter documentação de apoio no repositório;
* Controlar alterações por meio de commits claros;
* Manter a branch principal como versão estável.

## Correções e Atualizações

Caso seja identificado algum problema de segurança, a correção deverá seguir o seguinte fluxo:

1. Identificar o arquivo ou configuração afetada;
2. Corrigir o problema localmente ou diretamente pelo GitHub;
3. Revisar se não há novas exposições;
4. Realizar commit com mensagem clara;
5. Confirmar se o site publicado continua funcionando corretamente;
6. Atualizar a documentação, se necessário.

## Considerações Finais

A política de segurança deste projeto tem como objetivo demonstrar cuidado com a publicação de informações em repositórios públicos e com o uso do GitHub Pages.

Mesmo sendo um projeto simples e estático, a adoção dessas práticas contribui para uma entrega mais organizada, segura e alinhada com boas práticas de desenvolvimento.
