# Guia de Contribuição

## 1. Objetivo

Este documento apresenta orientações básicas para organização, colaboração e manutenção do PortfolioHUB.

Embora este projeto seja uma entrega individual, o uso de um guia de contribuição demonstra boas práticas de controle, revisão e colaboração em projetos versionados com GitHub.

## 2. Sobre o Projeto

O PortfolioHUB é um portfólio pessoal publicado com GitHub Pages, desenvolvido para apresentar informações profissionais, habilidades técnicas, projetos e formas de contato.

O projeto utiliza HTML, CSS e JavaScript, sendo mantido em um repositório público no GitHub.

## 3. Formas de Contribuição

Contribuições futuras podem ocorrer por meio de:

* Sugestões de melhoria visual;
* Correções de texto;
* Ajustes de responsividade;
* Melhorias de acessibilidade;
* Atualização de links;
* Melhorias na documentação;
* Inclusão de novos projetos.

## 4. Fluxo de Colaboração

Caso exista colaboração externa no futuro, recomenda-se seguir o fluxo abaixo:

1. Criar um fork do repositório;
2. Criar uma branch para a alteração;
3. Realizar as mudanças necessárias;
4. Testar o funcionamento do site;
5. Abrir um Pull Request;
6. Aguardar revisão antes da integração com a branch principal.

## 5. Padrão de Commits

As mensagens de commit devem ser claras e objetivas.

Exemplos recomendados:

* `docs: atualiza documentacao do projeto`
* `fix: corrige link de contato`
* `style: ajusta responsividade da pagina`
* `feat: adiciona novo projeto ao portfolio`
* `chore: organiza arquivos do repositorio`

Esse padrão facilita o entendimento do histórico de alterações.

## 6. Cuidados Antes de Enviar Alterações

Antes de enviar qualquer alteração, é importante verificar:

* Se o site continua carregando corretamente;
* Se os links estão funcionando;
* Se não há erros visuais;
* Se a responsividade foi mantida;
* Se não foram adicionados dados sensíveis;
* Se a documentação continua coerente;
* Se os arquivos alterados são realmente necessários.

## 7. Segurança

Não devem ser enviados para o repositório:

* Senhas;
* Tokens de acesso;
* Chaves de API;
* Chaves privadas;
* Dados pessoais sensíveis;
* Arquivos temporários desnecessários;
* Informações internas ou privadas.

Qualquer alteração deve preservar a segurança e a proposta pública do projeto.

## 8. Branch Principal

A branch `main` deve representar a versão estável do PortfolioHUB.

Alterações futuras devem ser revisadas antes de serem integradas, principalmente quando envolverem mudanças visuais, links, documentação ou estrutura do site.

## 9. Testes Recomendados

Antes de concluir uma alteração, recomenda-se testar:

* Carregamento da página inicial;
* Links de navegação;
* Links para projetos;
* Links de contato;
* Responsividade em tela menor;
* Visualização geral no navegador;
* Publicação correta pelo GitHub Pages.

## 10. Considerações Finais

Este guia de contribuição tem como objetivo manter o PortfolioHUB organizado, seguro e fácil de evoluir.

Mesmo sendo um projeto individual, a adoção dessas práticas contribui para uma melhor documentação, controle de versão e qualidade da entrega.
